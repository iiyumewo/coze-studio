# 多业务系统用户标识命名与隔离（待解决）

## 1. 状态

- 状态：待讨论，暂不实现
- 记录日期：2026-10-08
- 范围：Chat SDK、Coze OpenAPI、Conversation、Message、Run、Memory、业务扣费

## 2. 问题背景

当前业务前端按照以下格式生成 Chat SDK 用户标识：

```text
tenantId:userId
```

Chat SDK 将该值整体作为 Coze OpenAPI 的 `user_id`。Coze 把 `user_id` 视为由接入方定义和维护的外部用户标识，用于隔离会话、消息、记忆和变量；冒号及其两侧字段不是 Coze 规定的协议。

当前格式在单一业务系统内可以通过“租户 + 租户内用户”定位用户。但将来多个外部业务系统共用同一套 Coze 服务、智能体或接入凭据时，不同系统可能产生相同的 `tenantId:userId`：

```text
业务系统 A -> 10001:1
业务系统 B -> 10001:1
```

Coze 无法判断二者属于不同业务系统，可能把它们视为同一个终端用户。

## 3. 风险范围

- 会话列表和历史消息可能串到另一个业务系统的同名用户；
- Agent 记忆、用户变量和数据库用户维度数据可能相互污染；
- 文件检索和下载可能定位到错误会话中的附件；
- 用量统计、扣费通知和权益账户映射可能归属错误；
- 审计日志只有 `user_id` 时无法还原其来源业务系统。

上述风险成立的前提是多个业务系统共享会发生用户数据关联的 Coze 身份边界，例如相同 API 凭据、Connector、智能体或业务后端映射空间。即使当前链路中还有 `creator_id`、`connector_id` 等隔离字段，也不应依赖它们隐式消除所有碰撞。

## 4. 当前约束

1. `user_id` 是外部数据隔离标识，不是 Coze 登录用户 ID，也不是鉴权凭据。
2. 后端应把 `user_id` 当作不可拆解的字符串；文件工具等内部链路不得假设它是数字。
3. 当前 `message.user_id` 为 `varchar(60)`，新格式必须校验所有相关表和接口的最小长度限制。
4. 标识必须稳定。同一业务用户不应因昵称、手机号、登录设备或会话变化而改变。
5. 标识中不应直接放入手机号、邮箱等个人信息。

## 5. 候选方案

### 方案 A：增加业务系统命名空间

```text
systemCode:tenantId:userId
```

优点：改造直观，业务后端可以直接解析来源系统、租户和用户。

需要确定：

- `systemCode` 的注册和唯一性管理方式；
- 分隔符转义规则；
- 总长度限制；
- 是否增加格式版本，例如 `v1:systemCode:tenantId:userId`。

### 方案 B：使用统一身份服务生成的全局外部用户 ID

```text
externalSubjectId
```

由业务网关或统一身份服务维护“业务系统 + 租户 + 用户”到全局 ID 的映射。Coze 只接收不可解析的稳定标识。

优点：弱化格式耦合，便于未来合并账号或调整租户关系。

代价：扣费、审计和排障时需要查询映射服务。

### 方案 C：按业务系统完全拆分接入身份

为不同业务系统使用独立 API 凭据、Connector 或智能体，并确认所有 Conversation、Memory、Variable 和文件链路都包含该隔离维度。

该方案可以作为额外隔离措施，但不建议替代全局唯一 `user_id`，避免某条链路遗漏 Connector 维度后再次发生碰撞。

## 6. 初步倾向

短期优先考虑方案 A：

```text
systemCode:tenantId:userId
```

中长期如果外部业务系统数量增加、存在跨系统账号合并或统一权益账户需求，再评估方案 B。

本结论仅为待讨论方向，尚未形成实施决策。

## 7. 迁移注意事项

- 修改格式后，同一个自然人在 Coze 看来会成为新的 `user_id`；旧会话和新会话默认不会自动关联。
- 如需保留历史记录，需要设计旧 ID 到新 ID 的映射、查询兼容或数据迁移方案。
- 扣费接口不得长期依赖固定的冒号段数，应优先接收结构化的来源系统、租户和用户字段，或通过映射服务查询。
- 发布新格式前，应盘点 `conversation`、`message`、`run_record`、Memory、Variable、数据库和缓存键中的 `user_id` 使用方式。
- 应为两个业务系统使用相同 `tenantId:userId` 的情况增加隔离测试。

## 8. 后续决策清单

- 确认未来会接入的业务系统数量及其租户、用户 ID 唯一性范围；
- 确认是否共享 PAT、Connector、智能体和业务扣费账户；
- 选择方案 A、B，或二者结合；
- 定义长度、字符集、版本和转义规则；
- 确定历史数据迁移与兼容期限；
- 更新 Chat SDK 接入规范、扣费设计和 OpenAPI 示例；
- 完成跨业务系统会话、文件、记忆、变量和扣费隔离测试。
